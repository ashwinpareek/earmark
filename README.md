# Earmark

**Donations that can only pay the bill.**

Earmark is verified medical fundraising on PayPal. Before a campaign goes live, an AI reads the hospital's documents and plain rules check them. Each donation is a PayPal **hold**, not a charge. When the hospital submits its final bill, Earmark checks the bill against the verified estimate. It then charges every donor the **same fair share** of what the bill actually needs, pays the money **directly to the hospital**, and **releases the rest of every pledge, never charged**. The family never handles the money.

> Medical crowdfunding raises hundreds of millions of dollars a year on trust alone. Fake campaigns show a recurring pattern: no hospital named, a target that triples after launch, organizers who disappear, and verification that only happens after someone complains. Platforms that pay hospitals directly still take donors' money up front. Earmark removes the trust step altogether.

## How it works

```
Family uploads documents ─► Document Reader (multimodal AI) ─► Forensic rules ─► verified / review / rejected
                                                                                     │
Donors pledge ─► PayPal Orders v2, intent=AUTHORIZE (held, not charged) ◄────────────┘
                                                                                     
Hospital submits final bill ─► Reader ─► same rules + line matching + AI line classifier ─► payable amount
                                                                                     │
Settlement (integer cents) ─► per-donor partial capture (final_capture=true releases the rest)
                           ─► PayPal Payouts to the hospital's REGISTERED account ─► receipts + ledger
```

### The AI reads; rules decide

| Step | AI | Deterministic code |
|---|---|---|
| Read documents | **Document Reader**: reads photos, scans or PDFs and transcribes what's *printed* (never "fixes" numbers). It also reports visual tamper signals and copies any text that tries to instruct a reviewer | Zod validation, tolerant parsing |
| Verify a campaign | — | `forensics.ts`: hospital vs registry, arithmetic to the cent, one patient across documents (name, age vs date of birth), duplicate file or document number across *all* campaigns, dates, clinical support → verified / needs review / rejected |
| Check the final bill | **Bill Line Classifier**: medical care for the verified treatment, or not (parking, gift shop, visitor meals…) | `reconcile.ts`: same forensic rules, bill must be for the verified patient, line-by-line match to the estimate, covered growth > 15% over the estimate → human review |
| Move money | — | `settlement.ts`: largest-remainder allocation in integer cents. Every donor pays the same fraction, nobody is ever over-charged, and the totals are exact (property-tested) |
| Answer donors | **Campaign Q&A**: answers only from verified facts, check results and money figures | Facts are generated by code from verified extractions. No model can embellish them |

**Safety:**
- Every document and question is fenced as untrusted data.
- A document that addresses the AI is treated as fraud, not obeyed.
- A bill line the model forgets to classify is *not paid*.
- Money only moves to a hospital's registered PayPal account, never to an address printed on a document, and never to the organizer.
- Donors never see raw medical documents. The public views are redacted.

### PayPal integration

- **Orders v2** with `intent: AUTHORIZE` and **JS SDK** donate buttons: each pledge is a hold.
- **Authorizations**:
  - **partial capture** with `final_capture: true`, which automatically releases the uncaptured remainder of each donor's hold
  - **void** when a campaign is cancelled or a donor's share is zero
- **Payouts** to the hospital's registered PayPal account.
- **Webhooks** with signature verification (`/v1/notifications/verify-webhook-signature`).
- `PayPal-Request-Id` on every mutating call, for idempotency.
- Everything runs in the sandbox. A **mock mode** lets you run the app with no keys.

## Run it locally (5 minutes)

**You need:** Node 20+, a free PayPal developer account, and one AI key that can read images. A free Gemini key works.

```bash
git clone https://github.com/ashwinpareek/earmark.git
cd earmark
npm install
cp .env.example .env      # fill in the values below
npm run dev               # http://localhost:3000
```

1. **PayPal sandbox keys.**
   1. At [developer.paypal.com](https://developer.paypal.com/dashboard/), switch to **Sandbox**.
   2. Open **Apps & Credentials**, choose **Create App** (Merchant), and copy the **Client ID** and **Secret** into `.env`.
   3. Make sure **Payouts** is ticked in the app's features.
2. **Hospital payee.** Under **Testing Tools → Sandbox Accounts**, create (or use) a **Business** account. Put its email in `PROVIDER_PAYPAL_EMAIL` to watch hospital payouts arrive.
3. **Donor login.** The default sandbox **Personal** account is the donor. Log in with it in the PayPal popup.
4. **AI.** Set `GEMINI_API_KEY` ([get one free](https://aistudio.google.com/apikey)), or `ANTHROPIC_API_KEY` / `OPENAI_API_KEY`.
5. *(Optional)* `AG_STUDIO_LICENSE` removes the AG Studio watermark.

**Fallback modes:**
- With no PayPal keys the app runs in **mock mode**: simulated holds and captures, plus a "simulated donors" button.
- With no AI key, the bundled sample documents use a labelled answer key, so the demo still runs.
- A banner shows whenever a fallback is active.
- For judging, please use sandbox keys and an AI key.

### Webhooks (optional)

Add a webhook in your sandbox app pointing to `https://<host>/api/paypal/webhook` for these events:
- `PAYMENT.AUTHORIZATION.CREATED`
- `PAYMENT.AUTHORIZATION.VOIDED`
- `PAYMENT.CAPTURE.COMPLETED`
- `PAYMENT.PAYOUTS-ITEM.SUCCEEDED`
- `PAYMENT.PAYOUTS-ITEM.FAILED`

Put its ID in `PAYPAL_WEBHOOK_ID`. Unsigned calls are then rejected.

### Deploy on Render

`render.yaml` is included. Choose **New → Blueprint**, select this repo, and fill in the secrets. `RENDER_EXTERNAL_URL` is picked up for PayPal return URLs. The JSON data file lives on the instance disk and resets on redeploy, which is fine for a demo.

### Tests

```bash
npm test
```

There are 17 tests:
- **Settlement maths:** exact totals, fair shares, rounding, and 300 randomised invariant cases.
- **Forensic rules on the real sample documents:** genuine passes; doctored fails on exactly the right checks.
- **Bill reconciliation:** parking excluded, wrong patient rejected.
- **The AI code paths, with a stubbed model:** native image upload, tolerant parsing, skipped lines not paid, untrusted-input fencing.

## Project map

```
src/lib/
  reader.ts        Document Reader — multimodal extraction (Anthropic / OpenAI / Gemini)
  forensics.ts     Deterministic campaign checks with evidence
  reconcile.ts     Final-bill review: rules + line matching + AI line classification
  settlement.ts    Fair-share allocation in integer cents
  agents.ts        Bill line classifier, campaign Q&A
  workflow.ts      State machine: verify → live → bill review → settle (capture, void, payout)
  paypal.ts        Orders v2 authorize, capture, void, Payouts, webhook verification, mock mode
  providers.ts     Verified hospital registry (payees)
  views.ts         Role-based redaction (donor / family / hospital / reviewer)
src/app/
  page.tsx               Landing
  start/                 Start a campaign (upload + live verification)
  c/[id]/                Campaign page with role views; receipts
  hospital/  review/     Hospital billing portal, reviewer queue
  ledger/                AG Studio transparency ledger
scripts/make-samples.py  Generates the fictional demo documents
```

**Campaign states:** `verifying → live | needs_review | rejected`, then `live → bill_review → settling → settled`, with `bill_needs_review` and `cancelled` branches.

## Built with

- **PayPal:** Orders v2, Authorizations, Payouts, Webhooks, JS SDK.
- **AI:** Gemini, Claude or GPT, via one multimodal JSON client.
- **AG Studio + AG Grid:** the transparency ledger.
- **Render:** hosting.
- **Next.js 15, React 19, TypeScript, Zod.**

Demo limits: there is no login (roles are switched in the UI), and the hospital registry is a fixed list of fictional hospitals. Every person, hospital and document in the demo is fictional.
